Cross-Validation

Estimate how a model will do on new data by rotating which part of the data is held out. The honest way to tune.

01 The idea

K-fold cross-validation splits the data into $K$ folds, trains on $K-1$ and validates on the remaining one, rotating through all $K$. The average score estimates performance on unseen data; the spread tells you how much to trust it.

One train/validation split gives one noisy number: a lucky split flatters the model. Rotating the hold-out uses every row for validation exactly once and averages the luck away. With $K = 5$ or $10$, each model trains on 80–90% of the data, so the estimate is only slightly pessimistic.

The split must mimic how the model will be used. Stratify by class for imbalanced classification. Group by entity (customer, patient) when rows from one entity are correlated. Respect time order for forecasting: never train on the future.

In everyday terms

Instead of one exam, a student sits five exams, each made of questions they did not practise on, and the average grade is recorded.

02 Step by step

  1. Hold out a final test set and do not touch it.
  2. Split the rest into $K$ folds (stratified, grouped or time-ordered as appropriate).
  3. For each fold: fit everything (scaling, selection, the model) on the other folds, score on this one.
  4. Report the mean and standard deviation; pick hyperparameters by the mean.
  5. Refit on all non-test data and evaluate once on the test set.

04 The maths

  1. K-fold estimate

    $$\widehat{\text{Err}}_{\text{CV}} = \frac1K\sum_{k=1}^K\frac{1}{|F_k|}\sum_{i \in F_k}\ell\big(y_i, \hat f^{(-k)}(x_i)\big)$$

    $\hat f^{(-k)}$ is trained without fold $F_k$.

05 Key takeaways

  • Every preprocessing step that learns from data must happen inside the CV loop (use pipelines).
  • Nested CV (tuning inside, evaluation outside) is needed for an unbiased estimate of a tuned model.
  • Time series need forward-chaining splits.

06 In code

python
from sklearn.model_selection import cross_validate, StratifiedKFold, TimeSeriesSplit, GroupKFold
from sklearn.pipeline import make_pipeline
from sklearn.preprocessing import StandardScaler
from sklearn.linear_model import LogisticRegression

model = make_pipeline(StandardScaler(), LogisticRegression(max_iter=1000))   # scaling inside CV
cv = StratifiedKFold(n_splits=5, shuffle=True, random_state=0)
scores = cross_validate(model, X, y, cv=cv, scoring=["accuracy", "roc_auc"])
print({k: v.mean().round(3) for k, v in scores.items() if k.startswith("test_")})

Common pitfalls

  • Scaling or selecting features on all data before CV: leakage.
  • Shuffled K-fold on time series.
  • Random splits when the same customer appears in many rows.

07 Check yourself

Q1Why put the scaler inside the cross-validation pipeline?

Why: Fitting the scaler on all data leaks validation information.
