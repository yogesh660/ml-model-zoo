Embeddings and Positional Encoding

An embedding turns each token id into a learned vector, so that similar tokens end up close together. Positional encodings add the word order that attention would otherwise ignore.

01 The idea

A token id like 2746 is just a name: id 2746 is not “bigger” or “closer” to anything than id 12. An embedding replaces each id with a row of a learned table, a vector of a few hundred numbers, and training arranges those vectors so that their geometry means something: similar words point in similar directions.

The naive way to feed ids to a network is one-hot vectors: 50,257 numbers, all zero except a single 1. They are huge, and every pair of words is equally far apart, so “cat” is no more similar to “kitten” than to “carburettor”. Multiplying a one-hot vector by a weight matrix just picks out one row of it, so in practice we skip the multiplication and look the row up. That table of rows is the embedding layer: a matrix of shape vocabulary × d.

The rows start random and are learned. Words that appear in similar contexts receive similar gradients and drift together (“You shall know a word by the company it keeps”). Directions in the space can become meaningful too: the step from man to woman is roughly the same as from king to queen. Word2vec and GloVe learned such vectors on their own; in a Transformer the table is simply the first layer and is trained together with everything else.

Self-attention compares every token with every other token but has no idea where they are: “dog bites man” and “man bites dog” would look identical. So a positional encoding is added to each token’s embedding. The original Transformer used fixed sine and cosine waves of different wavelengths; GPT-2 and BERT learn one vector per position; many current LLMs (Llama, Mistral) use rotary embeddings (RoPE), which rotate queries and keys by an angle that depends on position.

Embeddings at the input are static: “bank” has one vector whether it is a river bank or a money bank. After a few attention layers the vector is mixed with its context and becomes contextual. Those contextual vectors, pooled over a sentence, are the “sentence embeddings” used for semantic search and retrieval-augmented generation.

In everyday terms

A map of a city where every word is a building. At first the buildings are scattered at random. Over training, words that are used for the same purposes move into the same neighbourhood, and the streets between neighbourhoods start to mean something: walking “north” might always mean “more formal”, walking “east” “female rather than male”.

02 Step by step

  1. Tokenize the text into ids (see tokenization).
  2. Create an embedding matrix $E$ of shape $|V| \times d$ (for GPT-2 small: $50{,}257 \times 768$), initialised with small random numbers.
  3. For each id, take its row: $e_t = E[\text{id}_t]$. A sentence of $T$ tokens becomes a $T \times d$ matrix.
  4. Add a position vector $p_t$ for each position $t$ (sinusoidal, learned, or applied later as a rotation with RoPE).
  5. Feed the result into the first Transformer block. Gradients from the loss flow all the way back into the rows of $E$ that were used.
  6. Optionally reuse $E^\top$ as the output layer (weight tying), so the same table maps ids to vectors and vectors back to scores over ids.

06 The maths

  1. Lookup = one-hot times a matrix

    $$e = \mathbf 1_{\text{id}}^\top E = E[\text{id}, :] \in \mathbb R^{d}$$

    Mathematically a linear layer applied to a one-hot vector, implemented as an index operation because the one-hot vector would be enormous.

  2. Similarity is an angle

    $$\cos(u, v) = \frac{u \cdot v}{\lVert u\rVert\,\lVert v\rVert} \in [-1, 1]$$

    1 means the same direction, 0 unrelated, −1 opposite. Nearest-neighbour search over embeddings almost always uses cosine similarity or a dot product.

  3. Learning from co-occurrence (GloVe)

    $$J = \sum_{i,j} f(X_{ij})\,\big(w_i \cdot \tilde w_j + b_i + \tilde b_j - \log X_{ij}\big)^2$$

    $X_{ij}$ counts how often word $j$ appears near word $i$. Fitting dot products to log counts forces words with similar neighbours to have similar vectors. The lab on this page trains exactly this kind of objective.

  4. Sinusoidal positional encoding

    $$PE_{(t,\,2i)} = \sin\!\Big(\frac{t}{10000^{2i/d}}\Big), \qquad PE_{(t,\,2i+1)} = \cos\!\Big(\frac{t}{10000^{2i/d}}\Big)$$

    Each pair of dimensions is a clock ticking at a different speed: early dimensions change every token, late ones barely change across thousands. Any shift $k$ is a fixed rotation, so relative positions are easy to read off.

  5. What the first block receives

    $$x_t = E[\text{id}_t] + p_t, \qquad X \in \mathbb R^{T \times d}$$

    The original Transformer also multiplied $E[\text{id}_t]$ by $\sqrt d$ so the embedding is not drowned out by the position signal.

  6. Parameter count

    $$|V| \cdot d = 50{,}257 \times 768 \approx 38.6\text{ M}$$

    About 31% of GPT-2 small’s 124 M parameters sit in this one table, which is why output layers usually share (tie) it.

07 Key takeaways

  • An embedding layer is a learned lookup table: id in, vector out. It is trained like any other weight.
  • Closeness in embedding space (cosine similarity) reflects similar usage, not dictionary meaning.
  • Attention is blind to order; positional information must be added (sinusoidal, learned or RoPE).
  • Input embeddings are static; vectors after attention layers are contextual, and those are what sentence embeddings and semantic search use.

08 In code

python
import math, torch, torch.nn as nn

vocab, d, T = 50257, 768, 8
ids = torch.randint(0, vocab, (1, T))              # stand-in for one tokenized sentence

tok_emb = nn.Embedding(vocab, d)                 # the lookup table, vocab x d
pos_emb = nn.Embedding(1024, d)                  # learned positions (GPT-2 / BERT style)
x = tok_emb(ids) + pos_emb(torch.arange(T))      # (1, T, d): what the first block reads

# fixed sinusoidal positions (original Transformer)
def sinusoidal(T, d):
    pos = torch.arange(T).unsqueeze(1)
    freq = torch.exp(torch.arange(0, d, 2) * (-math.log(10000.0) / d))
    pe = torch.zeros(T, d)
    pe[:, 0::2], pe[:, 1::2] = torch.sin(pos * freq), torch.cos(pos * freq)
    return pe

# cosine similarity between two token vectors
cos = nn.functional.cosine_similarity(tok_emb.weight[ids[0, 1]], tok_emb.weight[ids[0, 2]], dim=0)

Common pitfalls

  • Comparing embeddings from two different models; each model has its own space and the axes do not line up.
  • Reading analogies like king − man + woman ≈ queen as proof of understanding: they work for some relations and fail quietly for many others, and they inherit biases from the training text.
  • Using the raw input embeddings of a Transformer as sentence embeddings; use a model trained for sentence similarity.
  • Forgetting positional information in a custom attention model, then wondering why word order has no effect.
