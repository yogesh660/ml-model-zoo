Next-Concept Modelling (NCM): beyond next-token prediction

Next-Concept Modeling (NCM) is an emerging coarse-to-fine approach to text generation. Instead of predicting one token after another, an NCM system predicts a hierarchy of discrete concept codes, then refines those codes in parallel into text. It is a promising research direction for reducing sequential decoding, but it is not yet a drop-in replacement for large language models (LLMs).

01 The idea

Autoregressive language models repeatedly run a decoder to choose the next token. NCM changes the unit of prediction: a multiscale encoder represents text as coarse and fine codes, and a transformer predicts one level at a time, with all codes within that level generated in parallel.

A sentence has broad meaning, phrase-level structure and word-level detail. NCM represents those scales explicitly instead of forcing one token stream to learn every scale at once.

Coarse-to-fine decoding trades one long chain for a short sequence of refinement stages. Positions inside a stage can be predicted together, creating an opportunity for lower latency on long outputs.

The hierarchy is learned: a multiscale residual vector-quantised autoencoder maps text into discrete codes, with finer levels carrying residual detail.

NCM still uses transformer components and a text decoder. The distinction is the representation and generation schedule, not the disappearance of language modelling.

In everyday terms

Imagine drafting a map. An autoregressive model draws one street segment at a time. NCM sketches the city outline, then districts, then streets; all streets in one district can be refined together.

03 The maths

  1. Hierarchical representation

    z = (z^{(0)}, z^{(1)}, \\ldots, z^{(L)}), \\qquad x \\approx D(z)

    Text $x$ is represented by discrete code levels and reconstructed by decoder $D$.

  2. Level-wise factorisation

    p(z \\mid c) = \\prod_{\\ell=0}^{L} p\\left(z^{(\\ell)} \\mid z^{(<\\ell)}, c\\right)

    The ordered product is across levels; codes within a level can be predicted in parallel.

  3. Sequential-work comparison

    T_{\\text{NCM}} \\approx L T_{\\text{stage}} \\quad \\text{vs} \\quad T_{\\text{AR}} \\approx N T_{\\text{token}}

    If refinement stages $L$ are fewer than output tokens $N$, sequential work may fall; actual latency also depends on hardware and memory movement.

04 Key takeaways

  • NCM means Next-Concept Modeling: a coarse-to-fine language-modeling framework, not a claim that LLMs are obsolete.
  • A multiscale residual VQ-VAE supplies discrete concept-code levels; a transformer predicts one level at a time.
  • Codes within a level can be generated in parallel, reducing sequential dependency on output length.
  • Quality, reconstruction fidelity, memory use and hardware utilisation must be measured alongside speed.

Common pitfalls

  • Calling NCM a proven replacement for LLMs: current evidence supports a promising generation schedule, not universal superiority.
  • Comparing wall-clock claims without reporting hardware, batch size, output length or baseline decoding settings.
  • Assuming parallel code prediction removes all sequential work: NCM still has an ordered refinement schedule and reconstruction pass.
  • Confusing concept codes with transparent reasoning traces: the hierarchy is a learned representation.

06 Check yourself

Q1What is the main difference between NCM and ordinary autoregressive decoding?

Why: NCM changes the representation and schedule: it predicts coarse-to-fine code levels, with parallel work inside each level.

Q2Why is “NCM replaces LLMs” too strong?

Why: NCM is promising, but its quality, memory and deployment trade-offs remain open.

Q3What does a residual code level contribute?

Why: Residual levels add information needed to reconstruct finer-grained text.
