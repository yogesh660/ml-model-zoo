## Planned lessons
- `content/curriculum.js` modules mix live ids (strings) with planned lessons (`['Title', 'Core'|'Extended'|'Capstone']`; a trailing ` ⚙` means a live lab is planned). Helpers `C()`, `X()`, `K()` build those arrays.
- Each planned lesson gets a stub page at `concepts/<slug(title)>/` (`plannedPage` in `scripts/build.js`); it is in the hub syllabus and search but not in progress counts.
- To write one: add the lesson to `content/*.js` with `id` = that slug, then replace the array with the id in the curriculum. Stubs for algorithm-style lessons live under `concepts/`, so add a redirect if the real lesson is a `models/` page.
- Paths carry a `track` (stats, ml, ds, dl, cv, nlp, ai) that drives the hub filter buttons.

## Lesson object (content/*.js)
- All prose uses `r\`…\`` (String.raw); `$…$` / `$$…$$` is KaTeX; `[[lesson-id]]` or `[[lesson-id|text]]` links (build fails on unknown ids).
- Common: `id, short, title, task ('concepts' or regression/classification/clustering), level 1–3, minutes, summary, lead, intuition[], analogy, steps[], math[{h, tex, p}], code, pitfalls[], quiz[{q, o[4], a, why}], related[], prereq[], labIntro, tryThis[], keywords`.
- Models also: `hyper[[setting, what, typical]], pros[], cons[], use, avoid, complexity[train, predict], glance{learns, family}, concepts[]`.
- Concepts also: `keyPoints[], usedBy[]`.
- Optional: `explainer: '<ex key>'`, `architecture: '<arch key>'`, `archIntro`, `labFile: '<extra labs file>'`.
- `task === 'concepts'` → page at `concepts/<id>/`, otherwise `models/<id>/`.
- Section order on the page: idea, how, architecture, watch (walkthrough), lab, maths, tuning/takeaways, when, code, results, quiz, related.

## Walkthrough player (explainers.js)
- `ex.key = el => player(el, { title, steps: [{ part, t, d, dur }], draw(g, s, p, time) })`.
- Canvas is 640 × 400 logical units; `s` = step index, `p` = 0→1 progress, `time` = ms for loops.
- Kit `g`: `text(s, x, y, {size, color, align, a, sans})`, `rr(x, y, w, h, r, {fill, stroke, w, a})`, `line(pts, {color, w, a, dash, arrow})`, `dot`, `ring`, `glow`, `flow(pts, time, {n, color, speed, r})`, `cellColor(v)`. Helpers: `ease`, `clamp01`, `lerp`, `alpha`, theme `T`.
- Captions (`d`) are HTML; `[[links]]` are NOT processed there. Mark made-up numbers as illustrative on the canvas.
- Every step's final frame (p = 1) must be fully visible: no text past x = 630 or y = 395, no overlaps.

## Architecture diagrams (architecture.js)
- Spec: `{ title, labels?: [dt1, dt2], total, items: [...], extra: {key: info} }`; register in `root.Labs.architectures`.
- Item: `{ id, kind: 'custom' | 'block' | 'input' | 'op' | 'attn' | 'vec' | 'nodes' | 'out', label, shape, color, w, h, draw?(g, l, t, cx, cy), badges: [[extraKey, text]], info: {title, tag, io, params, body, more} | 'extraKey' }`.
- Helpers for custom glyphs: `box`, `txt`, `el`, and `G.grid / chips / plus / ln / nodes / bars`.
- Use real numbers (shapes, parameter counts) and check that the sums add up.

## Content standards
- Plain, friendly English; explain the intuition before the maths; British spelling ("normalise").
- Facts must be checkable: real library APIs, real parameter counts; no invented ids, citations or benchmark numbers.
- Match the portfolio look: violet/cyan palette from `T`, DM Mono labels, glass panels; no new libraries.
