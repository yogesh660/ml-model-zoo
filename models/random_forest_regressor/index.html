01 The idea

Grow many deep trees, each on a bootstrap sample of the rows and with a random subset of features at every split, then average their predictions. Averaging cancels out the trees’ individual mistakes.

A single deep tree has low bias but high variance. Averaging $B$ independent estimates divides variance by $B$, but trees trained on the same data are correlated, and correlation limits the gain. Random forests attack the correlation by forcing each split to consider only a random subset of features.

Each tree only sees about 63% of the rows. The rest are "out-of-bag", a free validation set for that tree. Combining them gives an honest error estimate without a separate hold-out.

In everyday terms

Asking many independent appraisers who each looked at different houses and focused on different details, then averaging their estimates.

02 How it works

  1. For $b = 1..B$: draw a bootstrap sample of rows.
  2. Grow a deep tree on it; at each split, consider only a random subset of max_features features.
  3. Predict by averaging all trees.
  4. Use out-of-bag predictions to estimate test error and permutation importance.

Things to try
  1. With 1 tree the fit is blocky and noisy. Add trees and watch the average smooth out.
  2. Note how test RMSE stops improving after a few dozen trees.
  3. Lower max depth and compare: shallower trees average into a less detailed curve.

04 The maths

  1. Variance of an average of correlated trees

    $$\operatorname{Var}\Big(\frac1B\sum_b T_b(x)\Big) = \rho\,\sigma^2 + \frac{1-\rho}{B}\,\sigma^2$$

    As $B$ grows the second term vanishes, leaving $\rho\sigma^2$. Feature subsampling lowers the correlation $\rho$, which is where the forest’s strength comes from.

  2. Out-of-bag fraction

    $$P(\text{row not in a bootstrap sample}) = \Big(1 - \tfrac1n\Big)^n \to e^{-1} \approx 0.368$$

    About a third of the rows are left out of each tree and serve as its validation set.

06 When to use it

Strengths

  • Strong accuracy with almost no tuning.
  • Robust to outliers and irrelevant features.
  • Free out-of-bag error estimate; parallel training.

Limitations

  • Large models with slower prediction than a single tree.
  • Cannot extrapolate.
  • Less interpretable than one tree; impurity importances are biased toward high-cardinality features.

Reach for it when

A reliable, low-effort baseline for almost any tabular problem.

Think twice when

You need the last few percent of accuracy (try boosting) or tiny, fast models.

07 In code

python
from sklearn.ensemble import RandomForestRegressor
from sklearn.inspection import permutation_importance

rf = RandomForestRegressor(n_estimators=500, max_features=0.5, oob_score=True,
                           n_jobs=-1, random_state=0).fit(X_tr, y_tr)
print("OOB R2:", round(rf.oob_score_, 3), "test R2:", round(rf.score(X_te, y_te), 3))
imp = permutation_importance(rf, X_te, y_te, n_repeats=10, random_state=0)
print(sorted(zip(imp.importances_mean.round(3), X.columns), reverse=True)[:5])

Common pitfalls

  • Trusting impurity-based feature_importances_; prefer permutation importance on held-out data.
  • Tuning n_estimators as if it could overfit. It cannot; it only costs time.

09 Check yourself

Q1Why does a random forest sample features at each split?

Why: Without it, every tree would split on the same strong feature first and they would make similar mistakes.

Q2Adding more trees to a random forest generally:

Why: More trees means the average converges; it does not add flexibility to each tree.
