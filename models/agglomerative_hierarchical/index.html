Agglomerative Hierarchical Clustering

Starts with every point alone and repeatedly merges the two closest clusters, building a tree (dendrogram) of the whole hierarchy.

01 The idea

Begin with $n$ singleton clusters. At each step merge the two closest clusters. The full history of merges is a dendrogram; cut it at any height to get any number of clusters.

The interesting part is how "closest clusters" is defined, the linkage. Single linkage uses the closest pair of points, which follows chains and long shapes but is prone to chaining through noise. Complete linkage uses the farthest pair, giving compact clusters. Average linkage sits in between. Ward linkage merges the pair that increases total within-cluster variance the least, which behaves like a hierarchical k-means.

You do not need to fix the number of clusters up front: inspect the dendrogram and cut where there is a big vertical gap.

In everyday terms

A family tree run backwards: individuals form families, families form clans, clans form tribes.

02 How it works

  1. Compute pairwise distances.
  2. Treat each point as its own cluster.
  3. Merge the two clusters with the smallest linkage distance; record the merge height.
  4. Update distances to the new cluster (Lance–Williams formula).
  5. Repeat until one cluster remains; cut the dendrogram to get labels.

04 The maths

  1. Linkage criteria

    $$d_{\text{single}} = \min_{a \in A, b \in B}d(a, b), \quad d_{\text{complete}} = \max_{a, b}d(a, b), \quad d_{\text{avg}} = \frac{1}{|A||B|}\sum_{a,b}d(a, b)$$

    Each choice produces a different hierarchy from the same distances.

  2. Ward’s criterion

    $$\Delta(A, B) = \frac{|A||B|}{|A| + |B|}\lVert\mu_A - \mu_B\rVert^2$$

    The increase in within-cluster sum of squares caused by merging $A$ and $B$.

06 When to use it

Strengths

  • No need to fix k in advance; the dendrogram shows all scales.
  • Deterministic.
  • Any distance and linkage combination.

Limitations

  • $O(n^2)$ memory and at least $O(n^2)$ time.
  • Greedy: a bad early merge is never undone.
  • Sensitive to linkage choice.

Reach for it when

Small to medium data where the hierarchy itself is interesting (taxonomies, gene expression, document topics).

Think twice when

More than about 20k points.

07 In code

python
import pandas as pd
from sklearn.preprocessing import StandardScaler

df = pd.read_csv("datasets/raw/mall_customers.csv")
X = StandardScaler().fit_transform(df[["Annual_Income_k", "Spending_Score"]])
from sklearn.cluster import AgglomerativeClustering
from scipy.cluster.hierarchy import linkage, dendrogram
import matplotlib.pyplot as plt

labels = AgglomerativeClustering(n_clusters=5, linkage="ward").fit_predict(X)
dendrogram(linkage(X, method="ward"), truncate_mode="lastp", p=20)
plt.show()

Common pitfalls

  • Using single linkage on noisy data: one bridge point chains two clusters together.
  • Using ward with a non-Euclidean metric (not valid).

09 Check yourself

Q1Which linkage is most prone to "chaining"?

Why: Two clusters merge if any single pair of points is close, so a trail of points links distant groups.

Q2How do you get 4 clusters from a dendrogram?

Why: The hierarchy contains every number of clusters from 1 to $n$.
